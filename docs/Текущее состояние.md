## Причина исходного отказа и исправление
- До восстановления: Status=restarting, ExitCode=1, RestartCount=53, OOMKilled=false (снимок 15:15). В окне инцидента — PermissionError; в 15:18 установлен путь `/srv/n13/app/bot.py`, Errno 13. Приложение не могло читать собственный код и падало при запуске.
- Dockerfile запускает bot (UID 10001); COPY сохранял права исходников без нормализации. Добавлен `chmod -R a+rX` только для app/tools внутри образа. Источник изменения mode/владельца на VPS не установлен; umask 077 воспроизведён в CI как проверяемый сценарий, а не доказанный источник инцидента.
- CI 40176311442 — success: реальные Docker build из owner-only исходников, импорт app.bot и tools.prepare_data под UID 10001, read-only и без сети; bash-синтаксис recovery. 15 unittest прошли локально, в том числе /review и навигация с подменой Telegram API.
- tools/repair_code_permissions.sh: проверка scope/тома/чистоты checkout, сборка и импорт до остановки, архив всего data при остановленном PDD, пересоздание только pdd с compose.yml+compose.proxy.yml и --no-deps, сохранение .env/тома, rollback образа при провале runtime-проверки. Не меняет права базы, МИГБИ и Mihomo не перезапускает.

## Новое исправление меню — код, не VPS
- При запуске регистрируются setMyCommands (/start, /menu, /review, /help) и setChatMenuButton(MenuButtonCommands): отдельная кнопка Telegram «Меню» у поля ввода.
- Временный TelegramAPIError регистрации логируется только именем класса и не останавливает polling.
- /start при незавершённой настройке предлагает продолжить сохранённый шаг, открыть меню или явно начать сначала; nav:setup восстанавливает экран goal/country/category без изменения состояния и истории. /help добавлен, в главном меню также доступно продолжение настройки.
- 17 unittest прошли локально: проверка API методов регистрации и команд, восстановления всех трёх шагов и сохранения 20 ответов. Новый код требует отдельного безопасного обновления VPS, на момент записи не развёрнут.
