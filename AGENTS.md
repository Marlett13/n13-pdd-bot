# Обязательные инструкции N13

## Сначала память
Перед работой прочитай `docs/Текущее состояние.md`, затем нужные разделы `docs/История проекта.md`. Не начинай проект заново. Markdown — запись наблюдений; код, тесты, deployment и пользовательская приёмка — разные уровни доказательств. Старую историю сохраняй.

## Завершение каждой существенной задачи: редакционная запись
Это постоянное поручение владельца от 31.10.2026. Выполняй сразу при завершении задачи, не откладывай до пятничного экспорта.

1. Зафиксируй результат и источники в накопительной истории; обнови компактное текущее состояние.
2. Проверь существующие `n13-event` ключи. Для нового подтверждённого результата, существенного подтверждённого ограничения или проверенного эксперимента добавь читательский блок в `docs/История проекта.md` по формату ниже.
3. Если нового подходящего события нет, добавь в служебную запись завершения `Редакционный итог: no_event — <конкретная причина>`. Не создавай пустые события, дубли, выдуманные гипотезы и посты о каждом коммите.
4. Проверь дату, уникальность ключа, подтверждения и ограничения. В финальном ответе назови созданный ключ или причину no_event. Не называй задачу полностью оформленной в памяти, если этот шаг пропущен.

## Точный формат для сканера
Заголовок второго уровня и маркер идут подряд, без пустой строки:

```markdown
## YYYY-MM-DD | Понятное название события
<!-- n13-event:project-stable-event-key -->

### ✅ Подтверждено
Понятный читателю подтверждённый результат с точным масштабом проверки.

### 🔬 Требует проверки
Только реальный оставшийся вопрос, если он есть.

### Источники и ограничения (служебно)
Ссылки на commit/PR/run/реальные наблюдения, дата и уровень доказательств.
```

- Не копируй этот пример как событие. Маркер допустим только с ISO-датой, ASCII-ключом из букв/цифр/_/- (до 120 символов) и реальным подтверждённым содержимым.
- Дата — дата события, не экспорта. Ключ устойчивый; сохраняй между GitHub и Obsidian. Не меняй уже известный блок ради повторной доставки. Существенное исправление — новая связанная запись с причиной.
- `### 🤔 Гипотеза` необязательна: добавляй только существующую гипотезу, не выдавая её за результат. Проверка также необязательна, если открытого вопроса нет.
- Каждая читательская секция не длиннее 1500 символов. Внутри настоящего блока не используй code fence, Markdown-изображения или HTML img. Заверши блок следующим заголовком второго уровня перед обычными служебными заметками, чтобы они не попали в текст.
- Логи, ID, команды, секреты, личные финансовые данные и технические уровни доказательств оставляй вне читательских секций. Служебные источники — под отдельным заголовком, они не публикуются.
- Не называй CI пользовательской проверкой; deployment не доказывает работу всех сценариев. Если подтверждён только код/тест/установка, прямо укажи этот масштаб в читательском тексте.
- Для изображений укажи реальные источники и права/доступность в служебной части. Не создавай фиктивные доказательства.

## Публикация
Разметка даёт кандидата на согласование, не разрешение публикации. Никогда не нажимай кнопку владельца и не публикуй автоматически в обход согласования. Не запускай deployment только ради правки памяти. Документальные обновления не должны запускать дорогие CI/deploy без необходимости; используй принятую в проекте политику фильтров/skip. Не меняй чужие сервисы и реальные данные ради редакционной записи.
